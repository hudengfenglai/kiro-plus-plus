三步上手

先配 Provider，再启代理，最后把路由应用到 Kiro。

01

配置 Provider

填写 Base URL、API Key、默认模型，并决定要暴露给 Kiro 的模型列表。

02

启动本地代理

启动本地 endpoint，让 Kiro 的 CodeWhisperer / Q Developer 请求先进入 kiro++。

03

应用到 Kiro

写入可恢复的用户配置，再运行诊断，确认 Kiro 已经走本地路由。

使用方式

按你的习惯选择入口，但底层都复用同一套本地代理和配置逻辑。

桌面控制台方式

适合第一次接入、切换模型、看诊断和日志。

CLI 方式

适合脚本化或熟悉命令行的工作流：`configure`、`diagnose`、`restore`、`start`。

配置文件方式

适合先整理 Provider 信息，再让桌面控制台或 CLI 读取统一配置。

常见排错入口

先从最短路径排查，不要一上来改安装目录或怀疑 Kiro 本体。

Kiro 没有走本地代理

先运行诊断，确认 `localRegions` 是否已指向本地 endpoint。

模型列表不显示

确认模型列表已保存，必要时重新从远程 `/models` 拉取。

Chat 报错

查看最近失败请求，按 operation、status 和 requestId 定位问题。

恢复原配置

使用最近备份恢复 Kiro 用户设置，回到未接入前状态。
