产品能力

它解决的不是“能不能接”，而是“接进去以后能不能稳定用”

对 LinuxDO 这种技术社区，真正有说服力的是能安装、能恢复、能排错，不是空泛的模型列表。

本地 BYOK 路由

把 Kiro 的 CodeWhisperer / Q Developer 请求转到你的 Provider Key，不改原安装目录。

多模型协同

同一 API 下可挂多个主流模型，优先覆盖 DeepSeek V4 Pro / Flash 这类高频路线。

一键启停与恢复

BYOK ON 表示应用本地路由；BYOK OFF 表示恢复最近 Kiro 原始备份。

失败优先诊断

最近失败请求、脱敏摘要、Auto 模式阻塞、未支持操作都会直接暴露出来。

接入方式

给第一次接触的人一个最短路径

01

安装依赖并通过测试

先确认当前版本可构建、可打包、可运行，再谈发帖和分发。

02

在桌面控制台选择 Provider 预设

优先走 DeepSeek 或 DashScope，保存并测试后再改 Kiro 配置。

03

启用 BYOK 并启动 Kiro

确认 Diagnose 没有阻塞项后，再从 Launch 入口拉起 Kiro 发第一条消息。

桌面方式

npm install
npm test
npm run desktop:dev
npm run desktop:package

CLI 方式

node .\src\cli\main.js configure
node .\src\cli\main.js diagnose
node .\src\cli\main.js start
node .\src\cli\main.js restore

DeepSeek 示例

$env:KIRO_PLUS_PROVIDER = "openai-compatible"
$env:KIRO_PLUS_OPENAI_API_KEY = "sk-..."
$env:KIRO_PLUS_OPENAI_BASE_URL = "https://api.deepseek.com"
$env:KIRO_PLUS_MODEL = "deepseek-v4-pro"

可信度

宣传可以直接讲，但该说清楚的边界不能藏

它做什么

  • 本地代理
  • Kiro 用户配置备份 / 写入 / 恢复
  • 桌面控制台与安装包
  • 日志、诊断和单次模型验证

它不做什么

  • 不改 Kiro 安装目录
  • 不伪造账号
  • 不绕过授权或额度
  • 不把 API Key 写进 repo 配置

当前版本限制

  • 上游 SSE 仍是缓冲后转 Kiro event-stream
  • 安装后双入口还需要干净 Windows 机再做一次人工 smoke
  • 首发仅支持 Windows
